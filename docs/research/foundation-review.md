The helper's protections are appropriate for the trusted local-owner boundary: it validates the existing handle represents a zero-length single-link regular object without a reparse-point attribute, gets/pins the process user SID, constructs one concrete owner allow ACE, and uses `ReOpenFile` on the existing object rather than reopening its path. Requested `FILE_WRITE_DATA` with only `FILE_SHARE_WRITE` prevents a previously open reader from surviving permission tightening unnoticed; changing the DACL alone would not revoke that reader's handle. Owner and protected DACL are applied through `SetSecurityInfo`, then read back on the original writer handle and checked for exact owner, protected flag, one explicit expected ACE/mask and matching SID. The tests cover happy-path read/write, nil/closed/directory rejection, a preexisting reader and a populated file. OS administrators can still take ownership by privilege. The directory/ancestor owner must remain trusted: already-authorized security handles, directory replacement rights or same-user malware are not neutralized by changing one file's DACL.

## Findings requiring correction

### High: restore can turn an unrelated SQLite database into an accepted backup

`internal/cli/operations.go:141` opens the candidate using `storage.Open`. `internal/storage/store.go:103` calls `migrate`, whose `internal/storage/migrations.go:56` version-zero branch creates the complete MiskoAI schema. A valid unrelated SQLite file with `user_version=0` and an unrelated table therefore acquires empty facts/messages tables before `Integrity` examines it. It can pass and replace the operational database. The previous file is retained under a recovery name, which limits permanent loss but does not prevent a false successful restore or loss of active application data. The existing corrupt-backup test uses a 14-byte non-SQLite file and exits at the size check, so it does not exercise this case.

Validate candidates without initialization or migrations. Require supported schema version and expected tables/columns/indexes/triggers before installation; reject unrelated databases. Add a regression using a valid SQLite unrelated table and version zero, verifying rejection, unchanged target bytes and no success output. Also test a claimed supported version with missing required tables. Inspect and handle `check.Close()` failure before installation.

### Medium: storage operations change permissions of arbitrary existing parent directories

`internal/storage/store.go:55` unconditionally calls `os.Chmod(dir,0700)`. The helper is shared by `Open` and `Backup`; a user-selected backup path in an existing shared directory changes that directory's access, including before an existing destination is rejected. On native Unix, a backup under a shared project directory can remove group/other access to unrelated files; an elevated backup to `/tmp/backup.db` can even change `/tmp`. Documentation's instruction to use a dedicated directory does not enforce this boundary.

Only set permissions on a newly created dedicated application directory, or reject an existing directory whose mode is unsuitable without mutating it. Add a native Unix test with an existing 0755 directory, both successful and refused backup destinations, and assert its permissions remain unchanged. Windows mode tests cannot establish the Unix effect or owner-only ACLs.

### Medium: the total retry deadline does not cancel the actual request

`internal/provider/deepseek.go:189` derives a 60-second context inside `retrySafeStatus`, but its callback takes no context. The closures at `deepseek.go:123` and `search.go:45` capture the original context. An explicit 429/503 arriving late in the first request permits another request with a fresh transport timeout after the total retry budget expires. DeepSeek can approach 120 seconds with a background caller despite the declared 60-second budget. Caller cancellation still works; the derived total budget does not.

Pass the derived context into each callback and use it for the transport. Add a deterministic short-budget regression through an injectable internal retry timeout, or verify that subsequent HTTP requests carry the same absolute total deadline. Existing retry tests exercise only immediate responses and attempt count.

### Medium: header-valid corrupt images reach the paid vision request

`internal/cli/probes.go:40` uses only `image.DecodeConfig`, then sends all original bytes. This validates a header and dimensions, not image content. A PNG truncated after its valid IHDR can pass `DecodeConfig` while full decoding fails; corrupt payload/checksum or truncated JPEG/GIF cases likewise are not reliably rejected. `internal/provider/deepseek.go:82` checks only a MIME prefix and size, so arbitrary invalid base64 under that prefix also passes that lower boundary. Existing tests cover a correct PNG, plain text and size excess.

Perform bounded full validation after dimension checks, or define a validated-image constructor that cannot be bypassed by ordinary callers. Keep the pixel and encoded-size limits and assess peak memory when decoding. Add header-valid truncated/corrupt files, mismatched MIME/base64 and oversized dimensions tests; assert no provider call occurs for invalid inputs.

### Medium: bound-account QR status is treated as an IDC redirect

`internal/cli/probes.go:199` combines `binded_redirect` with `scaned_but_redirect`. The pinned [official login implementation](https://github.com/Tencent/openclaw-weixin/blob/24de5c9eb0dd5e595d7e2d090ed8a3f82870d42c/src/auth/login-qr.ts) handles `binded_redirect` as already connected with no new credentials (source lines 397–407). It does not use `redirect_host` for that status. Current CLI constructs `https://` from an absent host and returns endpoint rejection; with a host it polls a flow that has already ended.

Handle it separately and truthfully explain that existing authorization must be inspected; do not claim newly stored credentials. Add a mock status with no redirect host and assert no continuation request or credential write. The same source clears the pending verification code after `scaned` (317–321); the CLI retains `verify`, which should also be covered by a multi-status verification regression.

### Medium: streamed completion succeeds without a terminal choice finish

`internal/provider/deepseek.go:168` rejects an invalid finish reason only when present; after transport `[DONE]`, line 183 returns success without requiring any choice with a valid `stop`/`length` finish. A stream containing content then `[DONE]` but no completion event passes, and `poc stream` reports a live pass. `provider_test.go:35` currently explicitly uses such an incomplete fixture as the success case. A bare `[DONE]` also makes the provider method succeed, though the CLI separately rejects zero text.

Track the expected choice and require a valid terminal finish before treating `[DONE]` as successful completion. Add missing-finish, empty-DONE, unsupported-finish and valid terminal-finish fixtures. Validate that output already emitted before a later failure is not treated as a delivered complete reply when the future pipeline integrates streaming.

## Additional boundary observations

- Fact quotas are per scope (`internal/storage/memory.go:59`), while messages have a global 10,000 cap. Arbitrarily many new scopes make the fact table and FTS index unbounded. This is not currently a remotely exposed attack path because the foundation has no management/chat integration; introduce a global store or authorized-scope cap before exposing fact creation. Per-scope export remains bounded under ordinary API writes.
- QR parsing is not complete semantic validation: `StartQR` only requires nonempty code/display; confirmation at `client.go:331` allows missing user/origin and oversized/control-character credentials. The CLI `saveAuthorization` subsequently rejects missing user/origin, oversized fields and CR/LF token values, so this is not presently a bypass of persisted authorization. Move consistent bounds into the adapter, validate redirect status fields, and reject terminal control characters before printing untrusted QR display text. The present QR fixture deliberately accepts `private.example` as a returned redirect field; it tests parsing, not safe continuation.
- Verification stdin reading blocks without observing the five-minute context (`internal/cli/probes.go:186`); it also uses ordinary terminal echo despite the plan's “private terminal input” requirement. Bound/cancel input and hide echo if that privacy requirement is retained. This affects the explicit login CLI, not HTTP deadline enforcement.
- `Storage.Open` uses a background context for setup/migrations, and restore creates its timeout only after opening the candidate. Bound restore copy/open/validation under one caller operation deadline before installation. This matters especially for a supplied large or pathological SQLite candidate.

## Satisfied boundaries and evidence limits

The reviewed transport implementations restrict TLS endpoints, disable HTTP redirects and environment proxies, validate every DNS answer before dialing a selected numeric IP, retain TLS hostname verification and reject private/transition address ranges. No arbitrary search-source fetching is present. Remote response bodies do not enter production errors. Credentials are omitted from config JSON and normal CLI result output. Test transport replacement is application-owned and is not exposed to model or network input.

Scoped fact read/update/delete/clear/export and message operations include account/user predicates; no concrete cross-scope leak was found. FTS query syntax is generated from quoted terms and literal LIKE patterns. Transactions protect migration, fact-budget changes, claims and reply completion. Snapshot backup uses bound `VACUUM INTO`; it does not copy a live WAL file. Persistent claims preserve duplicate suppression across restart and ambiguous states. Future channel/conversation identity, inbox/outbox recovery and cursor atomicity remain Phase 2 work, not defects in a claimed complete product.

Dependencies are pinned in module/checksum files. `modernc.org/sqlite` is directly imported but currently marked indirect; `go mod tidy` should normalize that metadata. Source inspection does not replace dependency vulnerability or license scans. No current evidence establishes native Linux filesystem behavior, VPS RSS, live provider vision/stream correctness or independent WeChat client acceptance.

Root status documents still describe an earlier “no business feature/no automated tests” checkpoint; research notes correctly distinguish historical scoped runs, mocks and blocked live gates, but `sqlite.md`'s statement that restore is unimplemented is now stale. The primary should reconcile these at the phase boundary and retain all unresolved live/native gates. Phases 2–8 are intentionally absent under the master-task Phase 1 gates and are not reported as missing foundation features.
