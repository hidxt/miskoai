# Attachment integration preflight — 2026-10-10

This is source inspection for future implementation, not a completed pipeline, schema migration, network test or package credit. Engineering progress50%. Prerequisites remain the attachment envelope, completed CDN transfer, full allocation-aware image validation, shared vision primitives and bounded document extractors. Root inspected current agent, service, provider and storage sources; no behavior is changed by this document.

`agent.Incoming` currently carries text only. `Agent.Handle` refuses empty text, verifies fixed account/user before work, serializes actual work and persists ClaimMessage before command/search/model/send. A later attachment flow must forward only the admitted typed descriptor and relax empty caption only with a valid descriptor. It must reuse this claim and the existing single durable `sending` → strict-ACK send → CompleteMessage path; a separate attachment handler must not claim independently or send a second caption. `storage.ClaimMessage` already accepts empty genuine text while reserving reply bytes and retaining every prior state for deduplication. No placeholder, filename, OCR, document excerpt or assistant analysis should be copied into that text field.

`Agent.answer` currently builds one scoped/profile snapshot, performs only explicit current-caption search, and calls the shared model. Image/document integration must budget its genuine caption and lower-role external data with that same snapshot and preserve current tool authorization. Extracted text cannot be submitted to the deterministic command parser as though it were user input. Context building currently counts only string Content; typed text parts must enter the ordinary byte/token budget before activation, while binary encoding has its separate fixed image/request limits. Profile, fact, summary and retrieved data must retain lower-role placement. Any claim about a document must identify the actual bounded UTF8-safe visible excerpt, not the extractor's potentially larger128KiB output.

`provider.DeepSeek.request` currently resets its image count per ContentPart array. Shared-vision Task1 now explicitly requires a global one-image preflight before json.Marshal; do not wire multiple image-bearing messages into the current implementation. The planned WithModel clone must share the original netx.Client and its two-slot lifetime, and Core vision telemetry must report logical attempts/successful usage without creating another transport or billing claim. One media admission must cover actual transfer, validation/parser, encoding/model and cleanup; canceled or uncooperative real readers cannot release it early.

`Service.work` currently forwards only text and calls Observer.Wake after every durable successful sent result/inbox completion. `storage.completedCount`, derived watermark admission, SaveDerived and scoped clear intentionally count all sent rows, while history queries require nonempty genuine content and reply. Filtering completedCount during attachment integration would alter already-persisted watermark meaning and can invalidate old snapshots; do not make that incidental change. Future tests must prove attachment-only completions retain duplicate IDs but supply no fabricated USER history/candidate quote and do not trigger pointless summary calls over unchanged text history. The same proof must cover an actual later genuine-text wake, clear/restart and original summary CAS/watermark compatibility. Decide the smallest observer/eligibility amendment against these fixtures before operational wiring.

The future runtime gate must also exercise authorization/refusal before CDN, claim before each external effect, one supported item versus explicit unsupported/multiple items, provided length/MD5 mismatch, truncated/failed/canceled artifact cleanup, strict one-send ambiguity, injected document command text inertness, shared provider admission and Core/HTTP shutdown joining all actual work.
