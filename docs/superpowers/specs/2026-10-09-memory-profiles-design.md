# Persistent summaries, reviewed memory candidates and profiles

2026-10-09 design for the next subsystem; not implemented. Follows the existing Go/SQLite/native single-process requirement and owner autonomy. No real API/WeChat request or private-data service start during deferred validation. Storage schema3 is an ordinary compatible extension, not a SQLite replacement.

## Purpose

Make memory useful beyond short context while preserving provenance and isolation. Provide bounded asynchronous summaries, reviewable extraction of user statements and persistent custom expression profiles. Fixed safety/tool authorization remains in code; nothing generated by a model becomes a confirmed fact automatically. Keep existing explicit /remember and manual facts unchanged.

## Selected approach and alternatives

Use SQLite tables for summaries, candidates and profiles so consistent backup/restore includes them. Plain JSON sidecars would separate them from current SQLite backups; treating summaries as facts would erase their distinct trust/provenance. A single coalesced summary worker, triggered after16 additional completed messages, minimizes model calls; failures do not block chatting. No vector DB or tokenizer dependency.

## Storage3

Retain exact schema1/2 manifests and add an exact schema3 delta. Migrations validate old/effective-WAL data before writable admission, preserve prior files on refusal and never prune old data. Summary records are keyed by fixed account/user, at most16 scopes and8KiB UTF-8 text each,≤128KiB globally. Persist completed-history watermark and updated time. Summaries are derived, unconfirmed data; do not add them to facts or FTS facts.

Memory candidates are scoped, unconfirmed records with candidate ID, proposed content≤1KiB, original user-message ID≤512bytes, exact supporting quote≤1KiB and creation time. Global256records/256KiB proposed-content+quote, at most128 per scope. Only accept a candidate if its quote is a nonempty exact substring of the cited USER turn present in the selected history; assistant/search/document text cannot be evidence. This verifies provenance, not whether the candidate correctly interprets the quote. Show candidates for user review; no candidate enters confirmed-fact retrieval. Confirmation is an explicit authenticated administrative operation; atomically insert an explicit_user fact with confidence1 and remove that scoped candidate, respecting existing fact quotas. Rejection deletes only that candidate. Fact edits/deletes are scoped and existing behavior retained.

Profiles store scope/name ID, display name≤128bytes, description≤1024, style≤512, address≤128, reply length short/normal/detailed, humor0..3, sticker tendency off/low/normal. Global64profiles/128KiB serialized field payload;≤16 per scope. ID is ASCII1..64 [a-z0-9_-] and warm/concise/professional reserved builtin IDs. Active selection is scoped and must identify a builtin or an existing scoped profile. Deleting an active custom profile selects warm in the same transaction. No credentials/provider endpoints/permissions are profile fields.

Admission validates counts/types/individual byte lengths/UTF-8/control fields before Go payload materialization, including effective WAL and restored schema3. Normal read APIs enforce bounded fields within a single snapshot. Export/backup retains schema1/2 compatibility. Existing restore256MiB cap is unchanged.

## Summary worker

One worker and one coalescing wake channel of size1 for the initially fixed account/user. It reads last16 completed pairs and previous derived summary, preserving exact message IDs and roles; request text≤24KiB,≤40messages, total deadline60s/output≤1024tokens. Use the same DeepSeek text model client so its in-flight cap remains2 across chat and summary. Build fixed summary instruction plus quoted user-role data; no tools/search/media. Exclude deterministic commands from candidate evidence. Output strict JSON with summary and at most8 candidates, no unknown fields, total response≤16KiB; validate UTF-8/control, summary8KiB and exact quotes before atomic storage update. More candidates or invalid data reject the result; no partial guessed facts.

Trigger only after16 new completed messages beyond persisted watermark; coalesce repeated wakeups. A failed attempt records a safe code and waits at least60s before another trigger is eligible, under cancellation. No endless autonomous polling/API retry beyond existing explicit429/503 transport bounds. Shutdown cancels and joins actual work before DB close; do not abandon background goroutines. Status exposes counters/codes only, no summary/candidate/raw model payload. Quotas can reject extraction without affecting successful chat.

## Chat integration

After successful send/persistence, an injected observer can wake summary processing without blocking. Summaries load as quoted lower user-role data, with a≤2KiB display cap and context budget eviction; current input/fixed safety remain mandatory. Custom profile fields are quoted lower user-role expression data and cannot replace the fixed system policy. Builtin behavior persists when no custom active selection exists. Confirmed facts are the only retrieval records labeled facts. Changes take effect on the next message; in-progress calls use one captured snapshot.

## Local acceptance and separate gates

Synthetic tests require schema1/2/3 strict admission and restore, scoped candidates/confirmation rollback/quota, invalid quote/assistant-source rejection, active-profile delete fallback and no-cross-scope reads. Summary tests cover coalescing, watermark/no double work, failure not blocking chat, cancellation/join, invalid structured output, generated content not confirmed and shared model admission. Agent tests cover derived-summary/custom-profile role and budget, current/safety preservation and hot snapshot consistency. Web surfaces/CLI lifetime are a later subsystem. Native Linux/race supplements Windows; actual cloud/WeChat and512MB results remain distinct and unverified for this subsystem.
