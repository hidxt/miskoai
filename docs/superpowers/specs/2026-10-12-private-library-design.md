# Private image/GIF library design

2026-10-12 root design under master15/19/21 and accepted attachment design. Engineering72%, no implementation credit. Brainstorming selected scoped SQLite metadata plus private immutable files, preserving the already approved single-process/database strategy. Alternatives (external media service, whole catalog in memory/SQLite blobs) increase runtime/resource/backup complexity and are rejected. Owner's continuous-development instruction authorizes routine internals; this design does not migrate actual private schema2 or authorize live/deployment/resource changes.

## Boundaries and bounds

Support administrator PNG/JPEG/GIF upload, tags/emotion/description, enable/disable/delete, hash/format/size/dimensions/frame metadata and recorded usage. No extra model call. Reply selection/sending belongs to package40; a library alone proves no native sticker/animated delivery. Existing off/low/normal profile fields remain the frequency policy input. New code must not activate message egress or change provider/channel/safety/parser limits.

Ceilings:128 metadata rows globally;64MiB summed content bytes globally;1..4MiB actual bytes per image; existing full image validator/64MiB decoder estimate; metadata description1024 UTF8 bytes, emotion64, at most16 distinct tags of1..32 UTF8 bytes, encoded tags JSON<=2048bytes; all text must be valid UTF8 without NUL, tag/emotion control characters refused. Dimensions/frames follow actual image validator and are never trusted from HTTP. ID is positive signed64-bit integer internally and canonical decimal string on Web. SHA256 is exactly64 lowercase hex. Scoped uniqueness is(account,user,sha256); duplicates return the original ID and never silently overwrite metadata/state/usage. Same payload in different scopes is distinct owned content. Scope components retain existing<=256 validation.

Compatible schema5 adds `library_assets`; old exact manifests1..4 and their restoration/admission remain supported. Actual private database is untouched; all migrations use synthetic fixtures. Ready rows are complete known content; deleting rows are disabled, nonselectable tombstones and still consume quota until owned file cleanup and row finalization. Missing/corrupt content never becomes selectable. Stored usage counters cannot overflow; no updates from model guesses. A library revision is unnecessary because backend mutations are serialized by one persistent library lifetime, but storage mutations remain transactional/scoped.

Opening/validating snapshots checks SQL types, scalar ranges, row count, summed payload/metadata bounds and enum constraints before materializing strings/JSON. Then validate each small admitted row and sequence metadata. New admission runs for immutable main DB and effective WAL before writable open/migration and in read-only backup validation, alongside all existing limits. Unknown tables/triggers/future versions still refuse. Legacy4 manifest is extracted verbatim from current DDL, not redefined around5.

## Media and filesystem lifetime

`media.StageLocal(ctx,dir,input,size)` streams exactly declared1..4MiB plus an EOF/trailing-byte probe into existing private spool and returns a completed immutable Artifact. No original name/path supplied; complete SHA256 uses fixed4096byte scratch. Partial/error ownership stays explicit and cleanup errors are safely classified. Spool identity, ACL, no link/reparse/replacement, Sync/Close/reopen checks remain. A reader must cooperate with context; no detached goroutine/false hard-time guarantee.

`attachment.ImageProcessor.WithLocalImage(ctx,input,size,consume)` reuses its existing persistent cap1 `slot`, calls StageLocal/full ValidateImage synchronously and lends only an Artifact plus computed ImageInfo and SHA256 through the consumer. Actual reads/consumer/artifact Close join before admission release; cancellation and cleanup failure are fixed safe classes with no raw strings. The processor continues to share this same slot with downloaded images/documents across generations/restore. No second decoder pool.

`internal/library` owns private persistent files and transitions. Content target is SHA256(length-prefixed scope plus binary content SHA256), with a fixed generated name under a dedicated private library directory; no DB/request path or original filename. Retain identity from the created open handle. Bound directory enumeration to128 known content entries plus a single upload stage; reject unknown entries, links/replacements/over-quota retained orphans and require reconciliation, never sweep them. Orphans consume actual disk admission and block unsafe further writes; row quota alone is insufficient.

Serialize library mutation/selected-content/export through one persistent admission. Lock order is library admission -> existing media admission -> store lease, and no caller may enter library while already holding a store lease. Core maintenance stops/joins generation before waiting for exclusive store access. Upload validates under media admission, creates/syncs immutable content without overwrite, then transactionally inserts metadata; duplicate handling compares scoped digest and original content. Failures remove only newly owned originals; uncertain cleanup remains a safe recovery state. Deletion first marks disabled/deleting, cleans only verified original content, then finalizes row. Ready read verifies scoped metadata before private open, actual size/hash/identity before lending. Metadata edit cannot change hash/format/size/scope/usage. Restart reconciles only explicitly known tombstones/originals with fresh verified handles; uncertain replacements refuse rather than unlink.

## Backup/restore compatibility

Existing SQLite backup/restore bytes and256MiB DB candidate cap are unchanged. It must be labeled database-only: library metadata is included after schema5; binary content is not. A database-only restore cannot imply library recovery: missing assets refuse selection and are reported as unavailable; old content is retained, never guessed/deleted. Preserve existing channel pause/reconciliation and prior-database recovery.

Add an explicit full-library bundle using a simple uncompressed, length-delimited version1 envelope; no generic ZIP/tar extraction. Fixed magic `MISKOAI-LIBRARY-1\n`, little-endian uint32 JSON header length<=65536, strict header containing db length1..256MiB and SHA256 plus<=128 ordered content records(key64hex,length1..4MiB,SHA256). Total content<=64MiB, total artifact<=321MiB, exact EOF/no duplicate keys/unknown fields. Snapshot is first made by SQLite's existing consistent primitive under joined library maintenance and is authoritative for the included rows/content. Stream DB then ordered content with4096byte scratch. The256MiB legacy path never accepts bundle bytes.

Prepare import into private stages before any destination mutation: bounded header/preflight, exact lengths/digests, exact schema/integrity/admission, compare every snapshot library row to its derived content record and full image validation. Acquire existing shared media slot for validation. Under maintenance and after generation/leases join, preflight destination physical count/bytes (including retained content), install only missing immutable objects with create-exclusive and captured ownership, and invoke existing validated DB restore. Existing matching files are reused only after complete checks. Space shortage refuses before install; do not clear current content to make space. On database-install failure remove only objects created by this import and preserve ambiguous recovery artifacts; existing files remain. On success keep previous referenced content for rollback, account it against physical limits, and leave channel paused. No combined filesystem/SQLite atomicity claim: explicit staged ordering and recovery evidence are mandatory.

## Core/Web and acceptance

Default Core owns one persistent library manager, shares existing media processor, and binds Store per captured generation lease rather than retaining a stale Store after restore. Borrowed dependencies remain borrowed. Authenticated fixed-scope API: list/page, upload raw bounded body with separately bounded metadata, edit metadata/state, delete, image preview and explicit bundle download/import. Reuse session/CSRF/same-origin/Host checks, no sniffing/CSP, canonical ID strings, private paths never returned. Preview exposes only checked complete supported image content to the administrator with correct MIME; no arbitrary file/network endpoint. UI renders all hostile fields as text, displays real availability/usage and distinguishes local library from unverified native sticker transport. Clear library editor IDs/cache on restore, as existing fact/profile restore reset does.

Acceptance requires reviewed schema/admission, exact legacy snapshots, actual full private content lifecycle/shared admission, deterministic quotas/foreign-scope checks, synthetic backup round-trip/failure recovery, real backend+UI and fresh independent review/root whole-product verification. No partial task earns39 credit. Native Linux race/systemd/arm64 runtime/live channel/512MB/final acceptance remain separate. Existing CoreM1/DOCX D062 follow-ups retained. Parser/resource/provider caps unchanged.

Self-review: scope and backup types explicit; lock order prevents maintenance inversion; immutable objects avoid overwriting current content; recovery refuses uncertain ownership and space shortages; partial-task interfaces below are preparation and cannot expose UI before backend. No invented live/resource evidence.
