# Native core, authenticated management and CLI design

2026-10-09. Root design for a later subsystem; not implemented. Dependencies: locally reviewed serial service and schema3/summary/profile integration. The owner has resumed bounded real WeChat tests handled separately by root; writing/testing this subsystem never starts an actual private-data service. Go/SQLite/embedded HTML/CSS/vanilla JS, one native process, loopback management and systemd remain fixed.

## Purpose and selected shape

Make the tested packages an operational binary with an embedded management UI. A core controller owns one data-directory lock, one store, one shared text/summary model client, one serial channel generation and one summary worker. Web calls a narrow controller interface; it never imports CLI or handles credentials. CLI can start/inspect/diagnose the same process. No separate frontend/parser runtime and no arbitrary model tools.

Use internal/core for lifetime, internal/web for bounded HTTP/auth/assets and internal/maintenance for shared stopped-store backup/restore mechanics. Factoring existing CLI operation code avoids cycles and duplicated file replacement logic. Narrow scoped store methods remain responsible for SQL; HTTP handlers cannot supply arbitrary SQL or choose other-user scopes. Initial service remains the fixed QR account/user; administrator routes are bound to that configured scope, not request-controlled scope strings.

## Configuration and credentials

Load a bounded strict non-secret settings.json from the selected dedicated private data directory. Environment overrides stored values; explicitly present invalid/empty environment values remain errors, never silently bypassed. Preserve old template fields during compatible loading and document authoritative effective values. DeepSeek official provider is fixed; model and vision_model remain configurable with deepseek-flash defaults. Context/output caps must match reviewed agent budgets. AI UI shows effective and desired settings and whether environment overrides them; model/context changes may persist for next restart with honest restart-required feedback. Profile selection/style changes use reviewed scoped SQLite APIs and take effect on the next message.

Credentials stay environment/verified owner-only files; admin password never appears in settings export, status, errors or command arguments. No automatically reading credentials from guessed paths. Explicit credential-file configuration may reuse the existing hidden-input file format after exact bounded schema/private-permission verification. Reading auth must validate complete strict JSON, configured fixed account/user and pinned service origin, not merely first JSON value. File/directory privacy must be established before payload read/write: Unix0600/0700 or Windows owner-only DACL, no symlink/reparse or unsafe inherited-reader access. Existing token-file protection is a reusable audited source, not proof of general Windows database privacy. Implement/test a shared private filesystem boundary before claiming Windows runtime privacy.

Text and summary use the same DeepSeek object. Future configured vision clone must share its netx transport/admission rather than independently constructing another two-slot client; total model concurrency stays2. No real request is part of startup/config/doctor tests.

## HTTP origin, auth and session boundary

Bind only127.0.0.1 or::1, with bounded header/request/deadline/concurrency limits. Exact configured Host including port and exact same Origin are mandatory for state-changing requests; never trust forwarded headers or reflect arbitrary Host into an accepted Origin. Default remote access is SSH forwarding the same local port. Reject unexpected Host even for assets to resist DNS rebinding. No CORS wildcard or public binding.

Use crypto/rand32-byte session and CSRF tokens, constant-time comparisons and SHA256 fixed-size in-memory admin-password verification; password16..256 bytes supplied privately. No reusable unsalted password hash is persisted. Password/session/token never in URL query or logs. Cookie Path=/, HttpOnly, SameSite=Strict, no Domain; loopback HTTP cookie semantics are documented honestly and TLS would additionally require Secure. Absolute session lifetime20min, at most64 active sessions; bounded cleanup on requests, no per-session goroutines. Logout removes session. Fixed-scope authenticated state-changing JSON requests require session, exact Origin and CSRF header. Login gets a bounded short-lived bootstrap nonce from same-origin UI, requires exact Origin and JSON content type, and consumes that nonce; CLI uses the same documented bootstrap/login flow. No login CSRF exception inferred from missing Origin. Rate limit shared local login attempts10/min with bounded table; generic failure responses and no attacker-controlled limiter growth.

Safe headers: restrictive CSP using same-origin external script/style only, no inline scripts/eval; frame-ancestors none, X-Content-Type-Options nosniff, Referrer-Policy no-referrer, Cache-Control no-store for authenticated/API/private data. User/model/profile/document content renders as text via textContent or escaped templates, never innerHTML/Markdown execution. Static assets only known embedded paths, no filesystem fallback. Panic/error handler emits only safe constants; HTTP error log omits payload, URL query, tokens and personal filenames.

## Management surface

Dashboard returns safe uptime, runtime Go allocation/goroutine/GC counts, channel/summary safe status, process counters and fixed last-error codes. Heap statistics must be labeled heap; native OS RSS/Peak RSS are separate platform measurements and unavailable where not implemented. No fabricated memory target pass. API counters distinguish chat/summary/vision/search attempts from token usage and current-process scope; service duplicate counter currently covers Handler duplicate result, not transport suppression.

AI displays official provider/effective models, bounded context/output settings, saved expression profiles and active selection. No key fragments or auth IDs/tokens. Memory supports bounded pagination/search, scoped fact add/update/correct/delete, candidates review/confirm/reject, safe derived summary display, context clear and full streamed valid JSON export. JSON export does not reuse the chat16KiB display limit. Read and mutation responses remain bounded/paginated; downloads use an authenticated POST preparation and safe fixed filenames, never URL session tokens.

System includes version/config validation, fixed safe recent event codes, synthetic local doctor, consistent backup download and stopped-channel restore maintenance. Events ring is bounded to128 safe enums/timestamps; no payload logging. Diagnostics never run external probes implicitly. Sticker surfaces join after the media/library subsystem; no clickable placeholder pretending upload/send works.

## Lifetime, quiescence and maintenance

Startup verifies private directory, obtains exclusive .miskoai.lock for the entire process, opens/admission-checks the store, constructs immutable dependencies and starts bounded HTTP/service/summary lifetimes. Missing channel authorization can leave authenticated management available with channel=unconfigured; configured real credentials are never used during development validation. Auth expiry pauses channel generation while HTTP remains available. No automatic login or QR refresh. Signal cancellation joins actual poll/handler/summary work, then shuts down bounded HTTP, closes store and releases owned lock. Stale lock is not blindly deleted; doctor reports safe operator recovery guidance. Startup/reconfiguration failures unwind all opened resources and do not expose unauthenticated management.

Controller serializes generation-changing maintenance; handlers never hold a store read lease while waiting for maintenance lock. Ordinary bounded scoped reads/writes take a store-generation read lease. Clear/restore acquires maintenance ownership, cancels and joins channel/summary first, then obtains exclusive store lease after existing bounded requests drain. Summary CAS also rejects older generated results. Backup obtains a consistent SQLite snapshot, releases store lease before downloading the completed private file and cleans after transfer/cancel. Never reopen a live private DB merely to make a backup. CLI backup against a running service must use authenticated local management or refuse with honest guidance; stopped standalone operations hold the same data-directory lock.

Restore streams one bounded<=256MiB private candidate, validates exact schema/integrity/admission before replacing anything, checkpoints/closes the old store only after all jobs/leases joined, preserves prior database and installs candidate with tested rollback/recovery. Do not delete unexplained old journals. Factor existing stopped CLI mechanics into maintenance; keep source/future-schema/corrupt/rollback tests. Restoring older snapshots also restores older receive/dedup history; the channel must remain paused after restore, and explicit owner reconciliation is required before starting external effects. No synthetic test or routine development command applies restore to actual private data. The final UI must state the retained prior snapshot and paused channel, rather than silently resuming a rolled-back conversation.
