# Core Lifetime and Maintenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Serial implementation and fresh task-review gates; authenticated Web is a separate plan.

**Goal:** Connect reviewed chat/summary/config/storage packages into a cancelable native controller with exclusive lifecycle ownership and reliable maintenance.

**Architecture:** maintenance factors existing stopped CLI mechanics. Core owns a fixed configured scope, shared provider instances, one store generation and joined channel/summary workers. CLI later runs the controller and bounded Web server under one cancellation lifetime.

**Tech Stack:** Go1.27.2, existing SQLite/privatefs/provider, no dependency or resident runtime.

**Spec:** docs/superpowers/specs/2026-10-09-core-web-design.md.

## Global Constraints
- Linux amd64/arm64 native process,512MB target, Go/SQLite, children only GPT-6.1 Medium, no delegation or live/private-data testing.
- Requires reviewed memory integration, runtime-config/privatefs and management-storage gates. No simultaneous ownership of CLI/storage files.
- Credentials remain private; status/settings/events cannot include keys, auth IDs, scope strings, personal filenames or raw errors.
- Fixed account/user from validated authorization; HTTP inputs cannot choose scopes. Missing authorization permits management-only; malformed existing auth fails safely.
- Actual poll/model/summary work is joined before store close; no abandoned goroutine or timeout that falsely frees its admission.
- Text and summary delegates reference the same underlying DeepSeek instance and its shared two-slot admission. Vision later shares that transport; search uses hosted Ollama only.
- Restore preserves a previous private database and keeps external channel effects paused across restart until explicit operator reconciliation. No implicit real startup in tests.

## Review Focus
- Constructor or HTTP bind failure unwinds owned resources and exclusive lock without deleting somebody else's lock.
- Slow actual model work cannot outlive clear/restore/shutdown and access a closed store.
- Request waiting for maintenance must not hold the store read lease; lock order is maintenance mutex first, then store-generation lease.
- Invalid/oversized/future restore leaves the original bytes and journals unchanged; successful restore never automatically replays older IDs.
- Missing authorization, missing provider key and expired authorization produce honest distinct safe state, never a fabricated ready state.

**Interfaces:**
- `Acquire(dataDir string)(*Lock,error)` verifies privatefs, exclusively creates .miskoai.lock through privatefs.Create before payload, and retains ownership for lifetime. `(*Lock).Close()error` idempotently closes/removes only the acquired object; identity mismatch refuses removal. Existing lock is never guessed stale/deleted automatically. Safe errors only.
- `Backup(ctx context.Context,s *storage.Store,destination string)error` uses the existing consistent Store.Backup. Caller holds lifecycle ownership; completed destination privatefs checked, never copy a live main file directly. `StoppedBackup(ctx,dataDir,destination string)error` acquires Lock before opening an existing private admitted DB, checks any existing journals' privacy, closes normal SQLite before releasing lock. Active service lock refuses with honest guidance; no implicit unauthenticated management bypass.
- `PrepareRestore(ctx context.Context,dataDir string,input io.Reader)(*Candidate,error)` exclusively creates private candidate, copies at most256MiB+1 with checked writes/context, Sync/Close, validates exact supported manifest/integrity/admission through existing Store APIs. Invalid input never changes current database. `(*Candidate).Discard()error` cleans only owned candidate artifacts through normal SQLite closure; never delete actual existing journals. Candidate path is private internal state, not status/error data.
- `InstallRestore(ctx context.Context,lock *Lock,candidate *Candidate)(RestoreResult,error)` requires the live exclusive lock acquired by this process for the candidate's exact data directory and stopped/closed old store. Nil, closed, mismatched-directory or replaced-identity locks refuse before installation; finding an existing lock file alone is not proof of ownership. Refuse unexplained old WAL/SHM; preserve main under exclusive unique pre-restore name, install candidate by rename, reopen/verify, roll back on installation/reopen failure. `RestoreResult{PreviousRetained bool; ChannelPaused bool}` contains no private path. A private persistent restore-pause marker must exist before installing any older receive/dedup state; marker-creation failure refuses installation. It is retained on success and conservative rollback, never silently deleted on crash.
- `RestorePaused(dataDir string)(bool,error)` reads a fixed owner-only marker through privatefs with strict known version/reason JSON within1KiB; absent=false, malformed/error=safe error. `ClearRestorePause(lock *Lock)error` requires a live identity-verified lock and explicit operator reconciliation from controller; not called automatically by CLI restore or startup.
- `StoppedRestore(ctx,dataDir,source string)(RestoreResult,error)` acquires Lock, uses verified private regular source<=256MiB, prepares/installs, preserves source, then releases lock. Existing CLI restore wrapper preserves visible prior-retained/paused guidance. Normal engine checkpoint/close remains required, no manual unexplained journal deletion.

**Root source preflight:** Store.Close closes the single SQLite connection normally; it does not expose an independent checkpoint method. Check close errors and require expected old journals to be absent before replacement; refuse retained/unexplained journals without deleting them. ValidateBackup is immutable/read-only and pins the exact supported schema/integrity before Store.Open admits quotas and migration on the private candidate. Resolve raw paths through privatefs.Resolve before filepath normalization, particularly restore source aliases. Source streaming verifies the opened file against checked metadata before reading and rechecks identity/size/time/privacy afterward. Candidate.Discard removes only its still-owned main file after normal engine close; it never guesses ownership of remaining journal files. Context checks in a copy loop cannot interrupt an arbitrary blocked Reader: join the actual reader operation and document this cooperative constraint; final HTTP upload deadlines bound network reads.

**Root pre-freeze durability correction:** On deployed Linux, sync the private parent directory after marker file Sync/Close/validation and before first target rename; valid existing markers also require this ordering. Check parent-directory sync after preserve/install/rollback renames before durable success. Failure before first rename preserves main/journal bytes; later failures retain pause and prior snapshot, recovering conservatively. Add TestRestoreDirectorySyncFailurePreservesBytes and rename-order/rollback-sync seams. Linux file-only fsync does not ensure directory-entry durability ([Linux fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html)); Windows development restart tests are not an equivalent power-crash directory guarantee. No actual power-cut test or private restore is inferred.

## Root gate and self-review
Both tasks retain existing provider/SQLite/native route and explicit danger permissions. Configuration/privatefs, scoped management storage, authenticated HTTP/UI and CLI integration have separate gates. Core does not import CLI/Web; Web imports a narrow controller contract, avoiding cycles. Shutdown ordering is worker join -> HTTP shutdown -> Controller.Close/store close/lock release, owned by final CLI. All five Review Focus cases have named tests. Root checks candidate cleanup, crash marker persistence, actual joins, generation lease order, shared model admission and safe error/status serialization. User autonomy supplies execution method; actual remote effects/restore tests remain prohibited outside prior bounded root authorization.
