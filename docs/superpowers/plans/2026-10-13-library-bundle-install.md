# Full library bundle installation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans. Root owns integration/Git. Continuous routine implementation is owner-authorized.

**Goal:** Install a completely prepared bundle while preserving prior referenced content, physical quotas and explicit database recovery ambiguity.

**Architecture:** One new operation on the existing active Maintenance view consumes its callback-bound PreparedBundle. Preflight the whole current/retained/incoming union before destination writes, repair only missing exact known content, retain the old references, create only absent admitted incoming objects, then invoke the trusted existing DB installation callback once. No combined filesystem/SQLite atomicity claim.

**Tech Stack:** Existing Go/privatefs/Processor/storage/maintenance/codec, no dependency/schema/provider/channel/deployment/resource change.

**Spec:** docs/superpowers/specs/2026-10-12-private-library-design.md; D069/D071/D077/D078 and Task7/9a contracts. Core/CLI/Web exposure and package39 acceptance follow after this independent library installation gate.

## Global constraints

- Child ONLY gpt-6.1-sol / medium; engineering74%. Synthetic-only. Main, actual private schema2, credentials/network/channel/server/Git untouched.
- Existing128 physical objects/64MiB actual bytes/4MiB per image, bounded metadata/cap1 Processor and generated contentName remain. Count each scoped generated key once, regardless of repeated current/retained/incoming references.
- Hold original Manager admission and active view/prepared ownership throughout. Trusted caller captures current LibrarySnapshot under this same maintenance admission, releases its short Store lease before calling installer, and stops/joins generation before exclusive DB replacement. No Store retained, detached cleanup or recursive Manager/media admission.
- Existing SQLite-only restore is unchanged. Full installation uses only prepared opaque maintenance.Candidate, original private stages and admitted rows; no raw path or arbitrary callback supplied from HTTP/model.
- Preserve existing files and uncertain objects. No overwrite, orphan adoption, sweep, quota relaxation, automatic reference expiry or channel resume. Failed installation remains recoverable/manual ambiguity rather than a false success.

## Review focus

1. Restoring an older valid scoped snapshot must leave the previous database's fully validated referenced images available for rollback, even after later metadata deletion/restart.
2. Current+retained+incoming count/bytes must fit before writes; corrupt/replaced/linked/unknown existing objects refuse without deletion, even if an imported digest happens to match.
3. Known missing ready/protected content may be repaired only from the exact admitted incoming key and immutable metadata; unrelated missing content refuses. Repaired referenced bytes survive later failure.
4. Before the DB callback, a failure may remove only newly created, identity-proven, unreferenced originals. After the callback starts, DB outcome can be ambiguous: preserve all new files and return recovery on failure, never guess active references.
5. Real copying/source/consumer/Sync/Close/directory-sync and DB callback work must join through cancellation/Manager.Close; copied/expired/foreign prepared objects refuse before effects.

- Create incoming-only missing targets using the same full create-exclusive/source/digest/Sync/Close/identity checks; reuse known matching existing originals only after complete checks. Keep a bounded list of newly owned unreferenced target identities, never paths from requests. Recheck all incoming destination originals and stage/candidate ownership before the DB callback. Complete actual destination directory sync before callback success can be claimed.
- Invoke trusted install(p.candidate) at most once, synchronously. The Core/CLI caller must call existing maintenance.InstallRestore under its existing lock, with current Store closed/released appropriately; it must not fake success, retain/discard the candidate or reenter Manager. Preserve returned PreviousRetained/ChannelPaused only from the actual result. Cancellation at callback return remains observable.
- Before callback entry, cleanup failure removes only newly created unreferenced exact originals after checking current/retained references and actual identity; uncertain replacements remain recovery. Referenced repairs and all preexisting/protected objects survive. Join actual cleanup and directory sync before admission release.
- After callback entry, any error/cancellation is conservatively recovery: preserve all destination files and monotonic catalog, because the database may have changed. Incoming-only leftovers can block later upload/install as unknown recovery objects until explicit operator reconciliation. This bounded conservative outcome is deliberate; do not infer active DB rows or auto-sweep from an error. PrepareBundle still joins its own raw stages and opaque candidate ownership handling. No DB/filesystem atomicity or physical power-loss guarantee.
- Safe fixed classes preserve context and ErrCleanup/ErrRecovery, never arbitrary callback/OS strings. A nil-error callback result is accepted only under the documented trusted existing-install contract; new tests use actual maintenance.InstallRestore rather than a spy claiming a restored database.
