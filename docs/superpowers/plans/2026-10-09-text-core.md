# Text Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkboxes; root integrates/reviews/commits after each independently tested module.

**Goal:** Produce authorized, bounded, restart-safe text orchestration and persistent receive primitives without new real API requests.

**Architecture:** Existing Go providers/channel/store plus internal/agent. Durable SQLite inbox and cursors own work; a serial runtime worker will consume it. Sender and model/search are narrow injected interfaces.

**Tech Stack:** Go1.27, stdlib, existing pure-Go SQLite; no new dependency.

**Spec:** docs/superpowers/specs/2026-10-09-text-core-design.md.

## Global Constraints
- Go modular monolith; SQLite; one resident process; no container/WSL/local model/extra resident runtimes.
- Linux amd64/arm64,2C/512MB targets require actual later authorized VPS measurements.
- DeepSeek text/vision deepseek-flash; Ollama hosted search; configured official endpoints.
- Only GPT-6.1 Medium/Low child agents, selected by root; no child delegation.
- No further actual cloud or WeChat requests under current spent/deferred live allowance.
- Fixed authorization precedes all side effects; no ambiguous send retry; private data never in logs/Git.

## Review Focus
- Restart between raw receive, inbox commit, claim and send: retain evidence and never duplicate a possible send.
- Same message ID across scopes: each authorized scope independent; no cross-user read/update/delete.
- Capacity during ingest/answer persistence: rollback cursor or reserve reply space before remote send.
- Malicious retrieved content/output: data cannot alter tool authorization; input/output stays bounded and valid UTF-8.
- Old snapshots/migrations: exact schema validation with read-only old version acceptance, no initialization of foreign files.
