> For agentic workers: use superpowers:subagent-driven-development; root integrates after fresh review.

Goal: deterministic, conservative optional image choice for an ordinary successful text reply under owner-approved D082, using one already-captured profile and a bounded scoped library snapshot. This task is pure inactive code; no Agent.Handle change, Store access, upload, send, tool or model call.

Architecture: NEW internal/agent/image_selection.go and image_selection_test.go plus docs/superpowers/reports/2026-10-14-image-reply-selection.md (three owned paths). Define narrow unexported input/result types and pure function for later orchestration. Input carries storage.Scope, inbound ID, genuine user text, validated reply, captured storage.Profile, <=128 candidate storage.LibraryAsset records, current UTC milliseconds and last confirmed image timestamp for that scope, and an explicit ordinary-success eligibility flag. Return only selected asset identity/snapshot and bool; no URL/path/token/key or execution authority. Profile comes from the same ChatContext snapshot used for the model answer; this helper never reloads it. Root later adds a consistent bounded Store query and supplies exact generation/Store binding.

Spec: REQUIREMENTS.md, SECURITY.md, current profile/asset admission, D082/D083. Continuous internal decisions are already authorized.

Root design ruling: builtin/empty/unknown/off profile disables selection. For an admitted custom profile low permits deterministic1/8 turns and normal2/8 using SHA256 of canonical JSON[scope.account,scope.user,inboundID]; byte0 modulo8 determines the gate. One scope cooldown low30minutes/normal5minutes from CONFIRMED image delivery; one asset cooldown24hours from its last confirmed usage. Zero means never confirmed. Future/out-of-range timestamps refuse selection; comparisons avoid overflow. These are conservative routine defaults implementing existing off/low/normal, not a delivery or resource guarantee.

Root design ruling: a candidate needs at least one nonblank trimmed/lowercased literal tag OR emotion present in BOTH genuine user text and validated model reply. Descriptions never influence ranking. No model-selected IDs or extra AI request. ASCII word tags require word boundaries to avoid substring accidents; non-ASCII literal matching remains bounded substring matching. Require matching scope, enabled ready single-frame PNG/JPEG and admitted exact ID/SHA/media metadata. GIF/animation/native stickers remain unsupported for automatic sends. Stable lowest positive asset ID wins among matching admitted candidates; ordering of supplied snapshot cannot change the choice.
