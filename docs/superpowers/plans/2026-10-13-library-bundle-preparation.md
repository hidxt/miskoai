# Full library bundle preparation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans. Root owns decisions/integration/Git. The owner authorized continuous routine implementation without additional process approval gates.

**Goal:** Export a consistent database plus fully validated scoped images, and prepare an incoming complete envelope in private stages before any destination mutation.

**Architecture:** Add synchronous operations to the existing admission-bound Maintenance view. Reuse SQLite BackupOwned, immutable snapshot admission, the accepted version1 codec and the actual shared cap1 image processor. A prepared object is lent only during its callback and invalidated/cleaned before the outer operation releases admission; no idle candidate pool or exposed private path.

**Tech Stack:** Native Go and existing privatefs/storage/maintenance/librarybundle/Processor; no dependencies, schema or runtime services.

**Spec:** docs/superpowers/specs/2026-10-12-private-library-design.md, D069/D071/D072/D074/D076 and accepted Task7 retained-content contracts. This Task9a is preparation only; Task9b installation and Core/CLI/Web exposure follow separately.

## Global constraints

- Child model ONLY gpt-6.1-sol / medium; engineering74%, no39 credit. Never touch actual private schema2, credentials, provider/CDN/WeChat/server, main Git or root ledgers.
- Version1 magic/header/database/image/count/sum/total limits remain exactly codec65536/256MiB/4MiB/128/64MiB/321MiB. Stream with4096-byte scratch, never read a database or envelope into memory.
- Preserve existing Manager -> shared Processor -> short fresh Store lease ordering. Capture BackupOwned under one short lease, release it before snapshot/image/full-byte checks. Never retain a Store or detach callback/read/cleanup work.
- Borrowed readers/writers cooperate with cancellation and remain caller-owned. Output on any failure is uncommitted; callers must stage/sync/close before publishing or serving it. Do not stream an unchecked partial bundle into a successful HTTP response.
- No destination image/database/catalog install, overwrite, orphan adoption, sweep, automatic retained-reference expiry, channel activation, new pool or safety/resource change.
- Existing SQLite-only256MiB backup/restore remains unchanged. Native/power-crash/512MB/live/final gates remain separate.

## Review focus

1. Consistent backup metadata must match exactly the exported image records across all scopes; ready missing/corrupt bytes refuse, deleting missing bytes may omit, deleting present bytes must validate.
2. Envelope bytes/SHA/exact EOF must pass before SQLite migration, image validation success or a prepared callback; header keys and image metadata derive from admitted authoritative rows.
3. Copied/expired/nil Maintenance and prepared objects refuse before input/output/effects; actual readers/consumer/Sync/Close/cleanup join under cancel and Manager.Close.
4. Legacy empty-library database imports may migrate only their owned candidate after original wire hash verification; migrated bytes are never claimed to have the original database wire digest.
5. Replaced/linked/uncertain stage files or directories survive safe refusal; cleanup removes only exact newly owned originals, and an unresolved stage blocks another attempt rather than accumulating arbitrary artifacts.
