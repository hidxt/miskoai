# Bounded Text and DOCX Extraction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Serial independently reviewed tasks; PDF and media transport have separate later plans.

**Goal:** Extract strictly bounded TXT/Markdown and the reviewed DOCX subset without external runtimes or untrusted filesystem extraction.

**Architecture:** A single admitted parser calls context-aware bounded readers. ZIP metadata and every member are admitted before XML extraction; a lexical guard bounds XML allocations before stdlib Decoder.Token. Input is an immutable private completed spool supplied by the media/controller boundary, never a user filename or arbitrary URL.

**Tech Stack:** Go1.27.2 stdlib only, no new dependency or resident runtime.

**Spec:** docs/superpowers/specs/2026-10-09-attachments-design.md and docs/research/docx-bounds-design.md.

## Global Constraints
- Children only GPT-6.1 Sol Medium (gpt-6.1-sol, reasoning_effort medium), no delegation, real files, cloud/media calls or actual service startup. Root owns integration, source/license and final resource acceptance.

- Input4MiB, actual aggregate DOCX decoded bytes8MiB, extracted UTF8 text128KiB, at most64 logical pages, one admitted parser and cooperative2s context. Keep admission until actual parsing ends; never abandon a timeout goroutine.
- Source/extracted text remains lower-role external evidence, not genuine USER caption or automatically confirmed fact. No HTML execution, link/relationship fetching, nested-archive extraction or writes under supplied filenames.
- Complete extraction or safe ErrLimit/ErrInvalid/ErrUnsupported/ErrEmpty/ErrCanceled; never successful truncation, payload/error/path leakage or a hard elapsed/RSS claim.

## Review Focus
- Small archives with huge metadata/counts/declared lengths refuse before stdlib allocation, including ZIP64 and ambiguous EOCD/base offsets.
- Valid decoded prefixes with CRC zero mismatch, compressed trailing bytes or local/central disagreement cannot produce success.
- Huge XML tokens/depth/attributes are guarded before Decoder.Token builds them; entities/DTD cannot trigger external work.
- Split UTF8/BOM/cancellation and exact limits produce complete valid text or honest failure, not substituted or silently truncated text.
- Saturated/canceled parsing retains one-worker admission until actual reader/parser returns, with no leaked worker or detached I/O.
