## Implemented behavior

All new writes use transactions, validate caller scope and positive signed64-bit IDs, and retain existing single-connection storage serialization. `LibraryAsset` and `LibraryMetadata` match the plan's interfaces. Implemented `AddLibraryAsset`, `LibraryAssets`, `LibraryAsset`, `UpdateLibraryAsset`, `MarkLibraryDeleting`, `FinishLibraryDelete`, `RecordLibraryUse`, and trusted internal `LibrarySnapshot`.

New rows require ID/usage/last-used zero, matching caller scope, ready state and disabled selection. Scoped duplicates return the original complete row without mutation or new quota use, including enabled rows, recorded usage and deleting tombstones. Equal content hashes in different scopes produce distinct rows. Metadata edits cannot change scope/hash/format/content bytes/dimensions/frames/usage. Deletes first disable and mark a tombstone; only tombstones can be finalized. Tombstones retain row and summed-content quota. Usage requires enabled ready state, validates ordinary Unix-millisecond bounds and rejects MaxInt64 overflow. Exhausted AUTOINCREMENT IDs also return safe capacity failure.

Bounds are 128 rows globally, 64MiB summed content, 1..4MiB declared content bytes per row; dimensions1..8192 with width*height<=16000000; frames1..32, and non-GIF exactly1. PNG/JPEG/GIF only. Description1024 UTF8 bytes, emotion64, <=16 distinct nonempty tags of<=32 UTF8 bytes, canonical encoded tags JSON<=2048. Invalid UTF8/NUL is refused; tag/emotion control characters are refused. These are metadata bounds; storage does not validate actual content or relax the existing full image validator/decoder caps.
