Fixed JSON errors are `{"error":"safe_code"}`:400 web_json,401 web_auth,403 web_forbidden,404 web_not_found,405 web_method,429 web_rate,503 web_busy/web_random,500 web_internal. All responses carry Cache-Control:no-store; no CORS headers or access log is added. Headers include specified CSP, nosniff, Referrer-Policy:no-referrer. Panic values/stack and net/http diagnostic payloads are never emitted; responses/logging use fixed codes. Already-written supplied-handler responses cannot be retracted, so application response confidentiality remains that handler's obligation.

Allowed Origin is constructed only from validated options. Exact Host rejects hostname aliases, missing/wrong port, alternate family, and forwarded-host/proto assertions. Unknown methods and override headers refuse. Absolute-form/opaque/escaped path/request-target bypasses refuse. Auth routes reject any query. All routes ParseQuery completely and reject invalid escaping/semicolon and case-insensitive credential names password,nonce,token,csrf,session,MiskoAI_session,session_token,admin_password,api_key,bot_token. Other application query schema is deliberately the later management adapter's responsibility.

Bootstrap nonces are crypto32-byte random, digest-only, one-use and expire at60s; table max64 with request-time cleanup. Validated failed password attempts consume their nonce too. Sessions and CSRF are separate crypto32-byte random values; only digests/expiry enter the mutex-protected session table. Session table max64, absolute20min lifetime; reads/CSRF refresh do not extend it. Cookie MiskoAI_session is Path=/,HttpOnly,SameSite=Strict,MaxAge1200,noDomain; HTTP loopback uses noSecure. Supplied cookies are never adopted on login. Duplicate session cookies/Origin/CSRF header ambiguity refuse.

GET session mints and returns a fresh CSRF value and replaces the stored digest; old CSRF immediately refuses, new token permits an authorized write. Login returns initial CSRF. Concurrent tabs can invalidate each other's token on refresh; a consumer must refresh/retry accordingly. Raw session tokens travel only in Set-Cookie, never JSON.

The local strict JSON helper remains private and login-specific: complete bounded validUTF8 object, known required strings only, no null/nested/nonstring values, duplicate decoded keys/escaped aliases, unknown/missing fields, trailing data or unpairedUTF16 escapes. It validates bounded complete data before field materialization. Safe constants contain no password/config fields.
