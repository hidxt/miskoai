# Weixin send acknowledgement compatibility implementation

2026-10-09. Bounded Medium task, authorized by `.tools/reviews/ack-brief.md`.

## Cause and scope

The old SendText path used the shared bounded exchange through `call`, then required a non-nil ret pointer. A complete successful HTTP response with ret genuinely absent and a positive lossless uint64 message_id therefore returned ErrOutcomeUnknown. Root supplied controlled shape evidence (HTTP 200, full 34-byte JSON object, message_id present, ret/errcode absent) and owner-confirmed delivery plus explicit approval for the stricter alternative acknowledgement rule. This agent did not inspect a private response or credentials, contact a real API, access a database, or retry any send.

Changes are limited to internal/channel/weixin/client.go, new ack.go and ack_test.go, and this report. Generic login/poll status behavior and types.go are unchanged. SendText invokes the existing exchange exactly once with its existing 15-second total deadline, slot, headers, cancellation/error handling and 2 MiB response cap, then classifies the bounded bytes.

The classifier first requires complete valid UTF-8 JSON object syntax. It visits every top-level known field with Unicode EqualFold matching, rejects known duplicates and malformed/null statuses conservatively, and gives valid explicit -14 expiry priority across statuses and duplicates within that complete object. Other valid nonzero statuses become safe ErrService. Success is explicit integer ret=0, or genuinely absent ret with positive uint64 literal/decoded decimal-string ID and no error status. ID strings must contain only ASCII digits, decode to at most 20 bytes, and fit 1..18446744073709551615. Ret=0 retains its prior optional-ID contract even for an invalid optional ID; duplicate IDs still reject. Unknown nested values remain slices into the capped body and are scanned without maps, typed arrays or recursion. No response text or ID is returned or logged.
