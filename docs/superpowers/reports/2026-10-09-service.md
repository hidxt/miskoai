## Behavior and root clarifications applied

A successful poll body, including zero bytes, is persisted before any parsing. Invalid allowed text quarantines the complete original evidence without cursor advance. Existing quarantined frames stop receiving while already accepted inbox work may finish. Pending frames resolve before the next remote call. Inbox capacity retains the same persisted frame/cursor, wakes the worker and retries locally after at least one second; no repeat remote call replaces that frame. Empty/absent next cursor retains the prior cursor. Empty valid batches wait at least one second. Retryable transport/rate/service polling errors use 1, 2, 4, 8, 16, 30, 30... second delays, under cancellation.

Unknown sender/group/bot/generating or wrong-recipient envelopes are filtered before typed ID/text/context validation. Original body/object/array/count/status/cursor checks still apply. All original duplicate and Unicode-fold keys are visited; selectors retain encoding/json last-field semantics. Explicit -14 signals survive later duplicate status values and earlier malformed message shape. Top-level message IDs remain lossless uint64 decimals; the first nonempty item msg_id is the fallback. Text is type1-only joined with newlines, at most 16KiB, with nonempty bounded reply context. Unsupported media is ignored without a claimed read/seen side effect. Invalid timestamp metadata uses receipt time.

Authorization expiry/unauthorized cancels both account workers, including an active Handler context; Run stays alive until outer cancellation. Handler storage/capacity failures and unknown states retain inbox work and pause the account. Terminal sent/duplicate/rejected/failed/ambiguous results complete only the scoped inbox reference. Service cancellation never detaches inbox completion. Any earlier durable agent claim suppresses restart side effects. Pause status/cause is protected against a concurrent worker's late observations.

Counters are process-lifetime observations. Received counts normalized authorized entries after frame resolution, including repeat deliveries. Duplicate counts Handler State=duplicate only, per root ruling; storage receive-side suppression is not inferred or represented as a handler duplicate. Status contains no account/user/token/text/raw body/error message/URL. Negative usage components do not enter totals; integer totals saturate.

## Review fix round 1 — aggregate text allocation

Independent review approved the architecture with no Critical/Important finding and identified one Minor resource issue: concatenation previously allocated the full joined text before checking the 16KiB aggregate limit. Only `normalize.go`, `service_test.go` and this report changed in the fix round.

The existing Join/check operation was extracted without changing its externally observed result so the allocation boundary could be tested directly. `joinText` now uses a nonnegative 16384-byte remaining budget, subtracting each item length and each intervening newline only after a checked comparison. Oversized aggregates return before calling strings.Join. This avoids integer-addition overflow and allocating attacker-sized aggregate text; item/decoder/body limits remain unchanged.

New meaningful regressions:

- `TestNormalizeAggregateTextIncludesSeparators`: two bounded items totaling 8192+1+8191 bytes are accepted exactly at16KiB; 8192+1+8192 and16384+1+1 are rejected, despite every item individually satisfying its field limit.
- `TestRejectedAggregateTextDoesNotAllocateJoinedString`: six focused calls to the helper (AllocsPerRun warmup plus five measurements) with64 references to one synthetic16KiB item establish that rejected aggregate work allocates no joined-output string. The test isolates normalization admission from JSON parser allocations; it is not an RSS or end-to-end memory measurement.

Actual commands under the same native Windows/offline Go environment:

- RED: `go test ./internal/service -run 'TestNormalizeAggregateTextIncludesSeparators|TestRejectedAggregateTextDoesNotAllocateJoinedString' -count=1` — exit1. Functional boundary checks passed, while the allocation regression failed with `1.0 allocations/run`, proving that late joining allocated before rejection.
- GREEN after checked-budget implementation: `go test ./internal/service -run 'TestNormalize|TestOriginalEnvelope|TestDuplicateSelectors|TestRejectedAggregate' -count=1` — exit0,1.852s.
