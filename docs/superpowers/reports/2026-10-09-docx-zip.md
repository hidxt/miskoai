## Restricted ZIP behavior

Admission refuses declared input over4MiB before I/O. It scans one tail of at most65,557 bytes for EOCD signatures and accepts one unambiguous candidate ending exactly at input EOF. Candidates that end earlier, multiple complete candidates, or a later misleading signature refuse before the standard parser. Single-disk fields and exact disk/total counts are required. ZIP64 sentinels/extra fields, multipart records, inconsistent central ranges and archive base offsets refuse.

Before any standard-reader construction, admission enforces256 entries,256KiB central directory,512-byte names,4KiB extras and1KiB per-member comments. Central count and span must be exact. Variable field lengths and subtraction-based remaining ranges are checked before allocation/read. Extra-field framing is validated, with ZIP64 field0x0001 refused in both central and local records. Advertised decoded lengths across all members, including unused members, must total at most8MiB. Store compressed and decoded advertised sizes must agree at admission.

Names are valid UTF8 slash names with no absolute prefix, colon, backslash, NUL, empty/dot/dot-dot component or duplicate canonical key. A directory trailing slash is removed only for duplicate comparison, so `a` plus `a/` cannot bypass the rule. No name becomes a filesystem path. Encoded symlinks and special Unix file types, DOS volume records and nonordinary file modes refuse; ordinary directory entries have zero advertised decoded length and CRC. Only Store and Deflate are accepted. Flags are limited to descriptor bit3, UTF8 bit11 and Deflate option bits1–2 for Deflate only; encryption and other flags refuse.

All local names, versions, flags, methods, timestamps, CRC/sizes and extras are admitted before `zip.NewReader`. Descriptor local fields may be zero placeholders or the exact central values. Non-ZIP64 12-byte or signature-prefixed16-byte descriptors must agree exactly with central CRC and sizes. Each local/header/body/descriptor range is before the central directory and in bounds. Sorted ranges must tile `[0, centralOffset)` exactly, which rejects overlap, repeated local offsets, prepended bytes, hidden local records and unclaimed gaps. This intentionally excludes archive envelopes and ZIP padding. A signatureless12-byte descriptor whose CRC equals the optional descriptor signature is conservatively refused as ambiguous. Colon-bearing names are also outside this subset.

`zip.NewReader` is invoked only by member validation after admission. Every returned central field represented by the manifest, archive comment, count, names, extras, CRC,32/64-bit sizes, attributes, flags, methods, versions and raw timestamps must match. DataOffset must match the admitted body offset; local metadata/descriptors are rechecked because stdlib DataOffset itself does not reconcile them. Standard-reader/underlying error text is replaced with fixed document error categories.

Every member is decoded, including unused images, objects and nested ZIP-looking bytes. Nested bytes are treated as an ordinary member and never parsed recursively. Store uses OpenRaw directly; Deflate uses OpenRaw through an `io.Reader`/`io.ByteReader` adapter with no application prefetch. Raw compressed consumption is counted independently. Reads continue to true decoded EOF; exact decoded length, independent IEEE CRC including declared zero, and exact compressed exhaustion are mandatory. Truncated streams, trailing compressed bytes, CRC mismatch and valid prefixes followed by corruption refuse. Each Deflate decoder is closed on every return path, with a close error classified safely; Close is never used as proof of integrity.

The actual aggregate admission counter is8MiB for all members. Fixed4096-byte scratch reads shrink near the remaining quota to at most remaining bytes plus one EOF probe. An over-quota probe causes ErrLimit before retained append and returns no part/map; it is not successful truncation. Deflate may do bounded internal work before returning from a stdlib call. Retained selected buffers have total admitted content at most8MiB; Go slice growth can add capacity slack and transient copies. This is not an exact heap or RSS bound. Unselected members retain no payload buffer. Only `[Content_Types].xml`, `_rels/.rels` and `word/document.xml` are allowed selection keys, including keys whose value is false; every other key refuses before I/O. No filesystem writes, external relationship resolution or URL fetch occurs.

ZIP integrity does not establish valid XML, valid UTF8 XML payloads, supported DOCX content types, namespaces, page semantics or extracted text. Those remain Task3 responsibilities. No actual user DOCX files were used.
