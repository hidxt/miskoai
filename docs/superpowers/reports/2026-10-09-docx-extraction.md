## Implemented boundary and subset

Public `Parser.Extract` admits DOCX through the same single synchronous admission slot and call-entry cooperative two-second deadline as TXT/Markdown. DOCX performs reviewed `admitZIP` and `validateZIPMembers` first: all-member integrity and actual aggregate decoded admission complete before extracting text. It retains only `[Content_Types].xml`, `_rels/.rels`, and `word/document.xml`; every fixed part is required. Input remains 4MiB, aggregate decoded bytes 8MiB, output complete UTF8 text 128KiB, logical pages at most 64. Every error returns zero `Result`; no successful prefix escapes. PDF/unknown still refuse without reads. ZIP/TXT implementation and tests were not edited.

Each selected XML part passes a lexical reader before strict `encoding/xml.Decoder.Token`. A fixed 4096-byte source buffer and fixed 65548-byte token carry handle UTF8 and markup delimiters across splits. Start/end tags count all lexical bytes, including delimiters, at most 16KiB; start attributes count quoted-value assignments including namespace declarations, at most 128. Text tokens count raw UTF8 bytes; comment/CDATA payload and PI payload (including its target) each allow 64KiB, excluding their opening/closing delimiters. Every start, including a self-closing element, admits depth at most 64 before release. Quoted delimiter-looking data cannot close a tag. Guards reject directives/DTD, custom entities, malformed/truncated UTF8, raw illegal XML characters, numeric surrogate/illegal/out-of-range code points and unsupported encodings. Optional initial UTF8 BOM and UTF8 XML declarations are supported. Predefined and valid decimal/hexadecimal references are preserved through normal XML decoding. Decoder Strict is true, Entity and CharsetReader are nil. Decoder error text never escapes; lexical classification and cancellation use fixed safe errors.

The content-type root must use the exact package 2006 namespace and contain one fixed nonconflicting `/word/document.xml` document-main override. Macro/template/another main content declaration is refused. Root relationships must use the exact package relationships namespace, have unique ASCII NCName-style canonical IDs, and contain one officeDocument relationship with only `word/document.xml` or `/word/document.xml`, absent/Internal TargetMode. External or other TargetMode is refused. Other root metadata relationships are structurally admitted and ignored; their targets are never followed. ASCII relationship IDs are an explicit restricted subset. Consumed expanded attributes cannot be duplicated, including aliases; the decoder boundary conservatively rejects all duplicate expanded attributes.

The document root and officeDocument relationship must match either Transitional WordprocessingML 2006 or Strict purl namespaces. A single direct document/body main story is required. Mixed WordprocessingML namespaces, foreign local-name text masquerading, malformed supported structure and duplicate bodies are invalid. Unknown foreign/property/graphics subtrees are skipped whole with lexical guards still active. Main-story paragraphs/runs, tables/rows/cells, hyperlinks, structured document content, insertion wrappers and smart tags have bounded parent checks. This is a documented subset, not a full Word schema validator or renderer. AlternateContent, altChunk/subDoc, simple/complex field markers/instructions encountered in the consumed main story are unsupported. Headers, footers, comments, notes, graphics, deleted text, layout rendering and OCR are not extracted. Relationships, field content and imported documents are never resolved.

Within supported body paragraphs/runs, `w:t` preserves decoded XML text (including its spaces; ordinary XML line-ending/entity decoding still applies), `w:tab` appends tab, absent/textWrapping `w:br` appends newline, and page `w:br` appends newline and increments logical page count. Each supported paragraph end appends exactly one newline. Layout hints and paragraphs do not increment pages. Whitespace-only/scanned-like bodies return ErrEmpty. Column/unknown breaks are unsupported. Output admission occurs before every append and never truncates a successful result. Extracted text remains lower-role external evidence; this task does not implement agent provenance/file-chat presentation.
